# Contributing

- Open an issue explaining the design/workflow problem before adding a large new library or skill.
- Cite primary documentation and annotate the date you checked it.
- Keep skills narrow: triggers in the description; steps, deliverables, and boundaries in the body.
- Add a minimal positive/negative activation example to skill contributions.
- Confirm scripts work on Windows PowerShell and a Unix shell where practical.
- Run `python scripts/validate.py` and `python -m unittest discover -s tests -v` before sending a PR.
- Don't import unlicensed design assets, screenshots, logos, or source code.
