# v1.2.0 playground evaluation rubric

Score each dimension from 1 (not acceptable) to 5 (strong evidence). A score is not a claim of WCAG conformance.

| Dimension | 1 | 3 | 5 | Evidence to record |
|---|---|---|---|---|
| Visual hierarchy | Competing or unclear | Main task is discoverable | Scan path is immediate | Screenshots and reviewer notes |
| Component consistency | One-off states | Mostly shared patterns | States and spacing feel systematic | Token/component inspection |
| Usability | Core journey blocked | Journey works with friction | Search, filters and detail feel direct | Browser task walkthrough |
| Accessibility | Major keyboard/semantic issues | Automated checks pass; manual gaps | Keyboard, focus, reflow and AT evidence | axe plus manual checklist |
| Responsiveness | Overflow or clipped controls | Functional at target widths | Layout adapts without loss of priority | 375/768/1440 screenshots |
| Interaction quality | Actions are unclear | Most actions have feedback | States, recovery and focus are coherent | Test results and observation |
| Maintainability | Duplicated implementation | Reasonable local structure | Tokens, fixtures, contracts and scripts are clear | File/code review |

## Negative activation test

Prompt: “What is the current weather in Colombo? Answer briefly and do not inspect or use any Design Intelligence skill.” Expected result: no UI skill is invoked or cited. This is a manual agent-selection experiment; it cannot be proven from the application runtime.
