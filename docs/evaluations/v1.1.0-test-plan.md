# v1.1.0 evaluation plan

This plan evaluates installation safety, diagnostics, and agent discovery. Record observed evidence; do not infer activation from a prompt alone.

## Automated checks

From the repository root:

```powershell
py scripts/validate.py
py -m unittest discover -s tests -v
py scripts/doctor.py
```

Create a temporary project containing an `AGENTS.md` and an unrelated `.agents/skills/private/SKILL.md`. Run a dry run, install, repeat the install, and create a conflicting Design Intelligence file. Expected results: dry run makes no changes, unrelated content and instructions remain unchanged, identical files are skipped, and conflicts fail before modification. Use `--force` only to verify timestamped backups.

## Explicit skill invocation

In a new Codex session opened on an installed target, prompt:

```text
Use $design-system-selector to compare the existing project's UI component options. Do not install dependencies. State which skill you used and cite the files you read.
```

Expected result: the response follows the skill's workflow and names evidence from the installed skill or its references. This is a manual observation, not an automated assertion.

## Automatic discovery prompt

```text
I need to choose a UI component approach for this existing project. Inspect the project and use the most relevant installed Design Intelligence skill. Do not install packages or modify files. Report the selected skill and why.
```

Expected result: a relevant skill is selected based on the request and the target project. Record the exact response and files cited.

## Negative test

```text
What is the current weather in Colombo? Answer briefly and do not inspect or use any Design Intelligence skill.
```

Expected result: no design skill is invoked or cited. This tests that the pack does not activate for unrelated work.
