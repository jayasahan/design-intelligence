### Remaining advisory: release gate remains failing

Full audit now reports **five high affected packages from one underlying advisory**, GHSA-fc5q-39xc-vjpf / CVE-2026-112366: picomatch repeated-extglob ReDoS. The chain is plugin-react -> Vite -> picomatch and Vite -> tinyglobby -> fdir -> picomatch (deduplicated 4.0.7). npm propagates the finding to plugin-react, Vite, tinyglobby and fdir. The advisory affects <=4.0.7; the registry's latest and highest published version is 4.0.7, and upstream lists **no patched version**. `npm update picomatch` confirmed no supported update. npm's suggested major downgrades would reintroduce the baseline toolchain risks and were not applied.

This is a development-tool risk involving attacker-supplied glob patterns; the app does not expose a glob endpoint or include picomatch in its browser bundle. That is a scope assessment, not proof of exploit impossibility. Full audit remains an explicit failing CI gate; release approval requires an upstream fix or separately authorized risk acceptance. No exception is silently encoded.

## Bundle evidence and performance decision

Production builds were executed on the same Windows machine and Node 24 runtime. Values below use Vite's displayed decimal kB and gzip estimates.

| Build | JavaScript | Gzip JS | CSS |
|---|---:|---:|---:|
| Baseline Vite 4 | 1,033.61 kB | 316.28 kB | 4.93 kB |
| Vite 8 | 1,003.75 kB | 302.06 kB | 4.94 kB |

Reduction: 29.86 kB (2.9%) raw JS and 14.22 kB (4.5%) gzip. One observed build took 3.57 seconds before and 424ms after, but this is not a controlled performance benchmark.

The generated `dist/bundle-report.json` attributes rendered pre-final-minification bytes primarily to Data Grid (~759kB), React DOM (~537kB), MUI Core (~519kB), MUI System (~92kB) and grid virtualization (~57kB). These are module attribution estimates, not compressed network totals. The application and icons are small (~35kB and ~6kB respectively); tree shaking retains the selected components rather than bundling the entire icon catalog.

Route lazy loading offers little benefit: this is one overview screen and its directory is part of the initial task. Immediately mounting a lazy grid would still download it during startup, while deferring it until viewport entry adds loading/focus/testing complexity. Arbitrarily splitting vendor files changes caching but does not remove bytes from the initial dependency graph. This release keeps the code small and the >500kB warning visible. Further optimization is worthwhile if measured cold-start latency or expanded routes justify a deferred grid boundary; no runtime speed claim is made from bundle size alone.

## CI and release assessment

The frontend workflow retains push/PR triggers, Ubuntu, Node 24, correct working directory, npm ci, typecheck, unit/build, Playwright's `install --with-deps chromium`, browser/axe suite and report/screenshot uploads. Added read-only repository permissions, a 20-minute timeout, a full audit gate, and bundle report upload. The audit runs after the browser checks (also after failures), so its known advisory does not prevent browser verification from executing; its nonzero exit still fails the job. Python CI is unchanged. Playwright now serves the production build, validating the actual output of the upgraded bundler. Screenshot baselines are never updated by CI.

GitHub execution is **pending**: the local changes have not been pushed, so there is no run URL for this revision. Local Windows tests do not certify Ubuntu CI.

Manual screen-reader, 200%+ zoom, Windows high-contrast and touch-grid scrolling checks remain outstanding. Axe supports the audit but does not certify WCAG compliance. The bundle warning and unpatched development-tool advisory remain known issues. Release readiness is conditional on the audit resolution/risk decision, an actual Ubuntu workflow run and remaining human review.
